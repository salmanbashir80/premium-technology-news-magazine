# Phase 3.1: Critical Security & CMS Correction Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eliminate exposed staff credentials, prevent database role escalation, enforce a strict editorial approval state machine, secure admin routes, isolate demonstration content, and implement database-driven Edge SSR on Cloudflare Workers.

**Architecture:** Layered security model consisting of:
1. PostgreSQL database-level controls: Column-level permissions, strict Row Level Security (RLS) policies, immutable audit logs, and trigger-enforced state machine (`draft -> fact_check -> editorial_review -> approved -> published`).
2. Server-side session verification: Administrative route gating in React and Edge SSR.
3. Edge SSR with dynamic Supabase REST caching in Cloudflare Worker (`src/worker/index.ts`).
4. Demo isolation flag (`is_demo`) separating synthetic demo articles from genuine journalism across all feeds and sitemaps.

**Tech Stack:** Supabase (PostgreSQL 17, GoTrue Auth, PostgREST, RLS), Cloudflare Workers, React 19, TypeScript, Playwright.
